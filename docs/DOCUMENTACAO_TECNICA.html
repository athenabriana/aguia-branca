1. Visão geral

Demonstração em vídeo
Águia Branca Challenge, Sprint 1
https://youtu.be/vavpqs3Of_o

Aplicativo Android que conecta três perfis do Grupo Águia Branca no ciclo de inovação:

  • Líder publica orientações estratégicas e acompanha o impacto consolidado.
  • Operador cadastra ideias e pode vinculá-las a uma orientação.
  • Gestor avalia as ideias usando a matriz ICE (Impacto × Confiança × Facilidade), aprova ou rejeita, e gerencia os projetos resultantes.

A ideia que vira projeto e gera retorno aparece na dashboard do líder agrupada pela orientação estratégica de origem. Assim o líder enxerga quais direcionamentos geraram resultado real.

3. Arquitetura da solução

Três camadas: UI (Compose) → Domain → Data (Firestore). A camada de Domain define as interfaces e não depende de Android nem Firebase, então pode ser substituída sem afetar o resto.

Dependência sempre de fora pra dentro: UI e Data dependem de Domain; Domain não depende de ninguém.

6. Regras de segurança

As regras estão em firestore.rules e controlam o acesso por papel buscando o documento do usuário a cada requisição. São a fonte de verdade, mesmo se a UI esconder um botão, o backend rejeita ações não autorizadas. 

service cloud.firestore {
  match /databases/{database}/documents {

    function isAuth()     { return request.auth != null; }
    function userDoc()    { return get(/databases/$(database)/documents/users/$(request.auth.uid)).data; }
    function role()       { return userDoc().role; }
    function isOperador() { return isAuth() && role() == 'OPERADOR'; }
    function isGestor()   { return isAuth() && role() == 'GESTOR'; }
    function isLider()    { return isAuth() && role() == 'LIDER'; }
    function affected()   { return request.resource.data.diff(resource.data).affectedKeys(); }

    // regras por coleção (ver firestore.rules)
  }
}

8. Matriz ICE

ICE é um framework de priorização leve, comum em produto e inovação. Em vez de discutir cada ideia em comitê, o avaliador estima três dimensões em escala 1 a 10 e o score sai por multiplicação. A escala multiplicativa amplifica diferenças: uma ideia 9·9·9 = 729 fica visivelmente acima de 7·7·7 = 343, mesmo as médias estando próximas.

DimensãoEscalaO que medir
Impacto (I) 1 a 10 Quanto a ideia move o ponteiro do negócio se for implementada com sucesso. Receita gerada, custo reduzido, satisfação do cliente, alinhamento estratégico.
Confiança (C) 1 a 10 Quão certo o avaliador está de que a ideia vai entregar o impacto previsto. Baseado em evidência: dados, benchmark, piloto, experiência prévia. Penaliza otimismo sem lastro.
Facilidade (E, Ease) 1 a 10 O inverso do esforço. Tempo, complexidade técnica, dependências, custo de implementação. Quanto mais simples e barato, maior a nota.

8.2 Como aparece no app

  • Curadoria do gestor: três sliders 1 a 10 na tela de detalhe da ideia, atualizando o score em tempo real. O botão "Aprovar" usa o ICE atual da matriz; não há botão separado de "salvar avaliação".
  • Persistência: ao salvar pela primeira vez, a ideia passa de SUBMETIDA para EM_ANALISE e ganha o objeto ice = { impact, confidence, ease, score }. Aprovar a ideia copia o score para o campo priorityScore do projeto criado (snapshot histórico, ver §7.2).
  • Lista de projetos do gestor: badge "Prioridade ICE: N" aparece enquanto o projeto não está CONCLUIDO. Quando há ROI calculado, o ROI assume o papel de critério.

11. Build e operação

11.1 Comandos

# Compilar debug
./gradlew :app:compileDebugKotlin

# Rodar testes
./gradlew :app:testDebugUnitTest

# Gerar APK debug
./gradlew :app:assembleDebug
# saída: app/build/outputs/apk/debug/app-debug.apk

# Gerar APK release (usa keystore debug se não houver keystore.properties)
./gradlew :app:assembleRelease

# Instalar direto no dispositivo conectado por USB
./gradlew :app:installDebug

11.2 APK release

./gradlew :app:assembleRelease usa o keystore de debug por padrão. Para assinar com keystore próprio, criar keystore.properties na raiz com storeFile, storePassword, keyAlias e keyPassword (passos detalhados no README.md).

11.3 Setup do Firebase

O README.md tem o passo-a-passo completo (criar projeto, registrar apps com.aguiabranca.app e com.aguiabranca.app.debug, habilitar Auth/Firestore/Crashlytics, baixar google-services.json). Para publicar regras e índices: firebase deploy --only firestore.

11.4 Dados de demonstração

A carga inicial é feita por scripts Python externos (não versionados) que chamam a REST API do Firebase. Estado atual no Firestore de demo: 8 usuários (3 base + 5 operadores com pontuação distribuída), 4 orientações, 15 ideias entre todos os status, 5 projetos (1 concluído com ROI positivo).
